Privacy policy

This policy describes the current private Jarvis pilot operated in its owner's environment. There is no public user registration.

Information accessed and why

Google account identity (account identifier and verified email) binds each connection to the intended personal or work account. With read consent, Jarvis accesses Gmail message information and content, and events on the user's primary Calendar, to answer the user's bounded requests. These read permissions do not allow sending, editing or deleting email.

Separate optional authorizations support creating calendar events after explicit approval and reading a user-selected Drive file. Event invitations may be delivered to the recipients shown in the approval preview. These features are not enabled by the persistent read grant.

Storage and retention

Persistent OAuth access and refresh tokens are encrypted in the operator's database, using a key stored separately. Account identities and operational records are also stored locally. Audit records can include object identifiers, timestamps, selected metadata, action parameters and receipts. Full mail bodies are not automatically imported into a permanent knowledge base by the current read integration.

Content used for a read response is processed in memory. If the user requests details through Telegram, the displayed content becomes part of the Telegram conversation. Local operational records and backups remain until the operator removes or retires them; there is no automatic fixed retention period for all such records.

Sharing and external services

Requests are sent directly to Google APIs. Jarvis does not use a third-party OAuth token manager for this pilot. Telegram processes messages and replies sent through the Telegram interface under its own policies. An optional AI service classifies the user's written requests when enabled; the current Google read integration does not automatically send fetched mailbox or calendar content to that classifier. Information the user includes in a written request may be processed by that service.

Jarvis does not sell Google user data, use it for advertising, or use it to train general-purpose AI models. Access is limited to the visible, user-requested features described here. Jarvis's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Controls and deletion

You can revoke Jarvis access in your Google Account's third-party connection settings. Local disconnection removes the saved credential record but does not itself revoke Google's grant, remove older backups or delete Telegram messages. To request removal of locally retained records or backups, contact the operator. Manage Telegram conversation history separately in Telegram.

Revoking a Google grant can also invalidate other permissions issued to Jarvis for the same Google project and account. Reconnection requires new, explicit Google consent.

This information website

This site has no sign-in, forms, analytics scripts or advertising. It does not receive Google OAuth credentials or mailbox/calendar data. GitHub Pages hosts it and may process visitor IP addresses and access logs for security, as described in the GitHub privacy statement.

Contact and updates

For privacy, access or deletion requests, use the developer support email displayed on the Google consent screen or contact your installation's operator. Material changes to Google data use will be disclosed here and require any additional consent before the changed access is enabled.
